SINCRONIZZAZIONE OROLOGI - PRIMA DI UNA NUOVA SIMULAZIONE

Ferma l'orchestratore prima di correggere gli orologi.
Esegui una sezione alla volta sulla macchina indicata.
Non occorre impostare lo stesso fuso orario: deve coincidere l'ora UTC reale.
Questi comandi modificano/attivano la sincronizzazione oraria.

1. UBUNTU WAZUH MANAGER

Attiva il servizio di sincronizzazione disponibile nel sistema:

sudo timedatectl set-ntp true

Attendi circa un minuto, poi controlla:

timedatectl status

date -u --iso-8601=seconds

Cerca System clock synchronized: yes. NTP service: active da solo non prova
che l'orologio sia stato sincronizzato.
Se set-ntp segnala NTP not supported o la sincronizzazione resta no,
conserva l'output: serve verificare il servizio/sorgente disponibile.

2. WINDOWS-HR - WINDOWS POWERSHELL COME AMMINISTRATORE

Avvia il servizio Windows Time senza sostituire la sorgente gia configurata:

Start-Service -Name W32Time

Richiedi sincronizzazione con riscoperta della sorgente:

w32tm.exe /resync /rediscover

Attendi circa un minuto, poi verifica:

w32tm.exe /query /source

w32tm.exe /query /status

(Get-Date).ToUniversalTime().ToString('o')

Se Start-Service segnala che il servizio e disabilitato, oppure resync dice
che non sono disponibili dati di ora, non proseguire con il test:
comunica il messaggio e la sorgente restituita da query /source.
Non cambiare alla cieca i server NTP, i limiti di correzione o le policy del dominio.
Se Windows usa il controller di dominio, anche il suo orologio deve essere corretto.

3. CONFRONTO FINALE

Esegui a pochi secondi di distanza:

Su Ubuntu:

date -u --iso-8601=seconds

Su Windows PowerShell:

(Get-Date).ToUniversalTime().ToString('o')

Data, ore e minuti devono coincidere; i secondi differiranno del tempo
impiegato a passare tra le due console. Confronta anche con l'ora reale UTC.
Se restano ore di differenza, invia gli output prima di fare altre modifiche.

4. NUOVA PROVA




IDENTIFICARE LA SORGENTE ORARIA - COMANDI DI SOLA LETTURA

WINDOWS-HR - WINDOWS POWERSHELL

1. Verifica se la macchina appartiene a un dominio:

Get-CimInstance Win32_ComputerSystem | Select-Object Name, PartOfDomain, Domain

2. Mostra configurazione e sorgenti del servizio orario:

w32tm.exe /query /configuration

w32tm.exe /query /peers

UBUNTU WAZUH MANAGER - TERMINALE UBUNTU

3. Mostra la sorgente e lo stato del servizio systemd-timesyncd, se disponibile:

timedatectl timesync-status

Se il comando segnala che systemd-timesyncd non e disponibile, esegui:

systemctl list-units --type=service --all | grep -Ei 'timesync|chrony|ntp'

Inviare i risultati. Non impostare Ubuntu come server NTP di Windows senza
aver configurato un vero servizio NTP server: SSH e NTP sono servizi diversi.
Non sostituire la sorgente di dominio con server Internet prima di verificare
l'appartenenza al dominio e la raggiungibilita della sorgente autorizzata del laboratorio.

Solo dopo aver verificato l'allineamento, avvia una NUOVA sessione con AVVIA.cmd,
attendi il controllo iniziale, esegui i comandi di discovery e usa STOP.
La correzione non riscrive i timestamp delle sessioni o degli alert gia prodotti.
Controlla anche che config_hr.json abbia lo stesso agent_id degli alert Windows-HR.


VERIFICA ACCESSO NTP DELLE VM - SOLO LETTURA

Non avviare ancora una nuova simulazione. Eseguire ciascuna sezione
solo sulla macchina indicata. Questi comandi non cambiano orologi o firewall.

WINDOWS-HR - WINDOWS POWERSHELL

1. Verifica risoluzione DNS IPv4 della sorgente gia configurata:

Resolve-DnsName time.windows.com -Type A

2. Richiedi cinque campioni NTP senza cambiare l'orologio:

w32tm.exe /stripchart /computer:time.windows.com /dataonly /samples:5

Nota: stripchart e il servizio Windows Time possono usare porte sorgenti diverse.
Un successo qui non garantisce da solo che il servizio resync funzioni.

UBUNTU WAZUH MANAGER - TERMINALE LINUX

3. Mostra gli indirizzi IPv4 della sorgente Ubuntu:

getent ahostsv4 ntp.ubuntu.com

4. Mostra i messaggi recenti del servizio di sincronizzazione:

sudo journalctl -u systemd-timesyncd -n 30 --no-pager

Inviare i risultati. Ubuntu al momento ha selezionato un indirizzo IPv6:
questo non dimostra da solo che IPv6 sia la causa.
Non usare Test-NetConnection -Port 123 per verificare NTP: quel controllo
prova TCP, mentre NTP utilizza UDP 123.
Start-Service e un comando Windows PowerShell, non Ubuntu.



COMANDI ALLINEAMENTO
ALLINEAMENTO WINDOWS-HR A UBUNTU VIA SSH - SENZA NTP INTERNET

Per una prova breve e controllata usiamo Ubuntu Wazuh come riferimento
comune. Questa e una regolazione una tantum: non e una sincronizzazione
NTP continua e non certifica l'esattezza dell'ora UTC di Ubuntu.
Non modifica l'orologio Ubuntu, i fusi orari o le regole del firewall.

1. FERMA L'ORCHESTRATORE SU WINDOWS-HR.
La correzione dell'ora va fatta PRIMA di avviare una nuova sessione.

2. SU WINDOWS-HR APRI WINDOWS POWERSHELL COME AMMINISTRATORE.
Copia e incolla TUTTO il blocco seguente, da & { fino all'ultima }.
La password SSH viene richiesta dal client: non inserirla nel testo.
Il comando remoto date legge l'ora dopo l'autenticazione, quindi il tempo
impiegato a digitare la password non viene copiato come errore di orologio.

& {
    $righeOra = @(ssh.exe -T wazuh@10.0.99.14 'date -u +%s')
    if ($LASTEXITCODE -ne 0) { throw 'Lettura SSH fallita: ora Windows non modificata.' }
    $testoOra = ($righeOra -join '').Trim()
    [long]$secondiUnix = 0
    if (-not [long]::TryParse($testoOra, [ref]$secondiUnix)) { throw 'Risposta oraria non valida: ora Windows non modificata.' }
    if ($secondiUnix -lt 946684800 -or $secondiUnix -gt 4102444800) { throw 'Data del server fuori intervallo: ora Windows non modificata.' }
    $oraServer = [DateTimeOffset]::FromUnixTimeSeconds($secondiUnix)
    Set-Date -Date $oraServer.LocalDateTime -ErrorAction Stop | Out-Null
    Write-Output ('Windows UTC: ' + (Get-Date).ToUniversalTime().ToString('o'))
}

Il blocco cambia realmente l'ora Windows. Non eseguirlo durante una raccolta.
Se compare un errore, fermati e conserva il messaggio.

3. CONFRONTA NUOVAMENTE LE ORE, SEMPRE DA WINDOWS POWERSHELL.
Questo blocco legge soltanto. Copiarlo interamente.

& {
    Write-Output 'Ubuntu UTC:'
    ssh.exe -T wazuh@10.0.99.14 'date -u +%Y-%m-%dT%H:%M:%SZ'
    if ($LASTEXITCODE -ne 0) { throw 'Verifica SSH fallita.' }
    Write-Output ('Windows UTC: ' + (Get-Date).ToUniversalTime().ToString('o'))
}

Le ore UTC dovrebbero differire di pochi secondi al massimo su una rete locale.
Non e una garanzia di precisione NTP: c'e il ritardo di trasporto/elaborazione.
Se resta uno scarto grande, non avviare il test e invia l'output.

4. DOPO LA VERIFICA, AVVIA UNA NUOVA SESSIONE CON AVVIA.cmd.
Attendi il minuto iniziale, esegui i comandi di prova, poi STOP ed esportazione.
Confronta anche agent_id nel config con quello degli alert reali Windows-HR.

Non usare /resync per questa procedura: l'accesso NTP esterno resta un
problema separato. Le regole NTP gia aggiunte possono restare configurate.
Questo allineamento non corregge i timestamp dei log o delle sessioni vecchie.
Per prove lunghe servira una sorgente oraria stabile e raggiungibile.
Prima e dopo ogni sessione verifica che le due VM siano ancora allineate.



ORARIO LOCALE E UTC - NON SPOSTARE DI NUOVO GLI OROLOGI

Windows alle 04:36 AM puo gia essere allineato a Ubuntu alle 11:36 UTC
se il fuso Windows e UTC-7. Il fuso cambia la visualizzazione, non l'istante UTC.
Non copiare l'orario locale di una macchina sull'altra.
Ferma l'orchestratore durante la verifica/configurazione.

1. WINDOWS-HR - WINDOWS POWERSHELL COME AMMINISTRATORE
Mostra il fuso prima della modifica:

Get-TimeZone

Imposta il fuso italiano (non cambia l'istante UTC dell'orologio):

Set-TimeZone -Id 'W. Europe Standard Time'

Mostra ora locale e UTC:

Get-Date -Format 'yyyy-MM-dd HH:mm:ss zzz'

(Get-Date).ToUniversalTime().ToString('o')

2. UBUNTU WAZUH - TERMINALE LINUX
Imposta lo stesso fuso italiano:

sudo timedatectl set-timezone Europe/Rome

Mostra ora locale e UTC:

date --iso-8601=seconds

date -u --iso-8601=seconds

3. CONFRONTO DIRETTO VIA SSH, DA WINDOWS-HR
Il blocco seguente NON cambia l'ora: confronta l'orologio del manager
con quello Windows, indipendentemente dal fuso. Copialo interamente.

& {
    $righeConfronto = @(ssh.exe -T wazuh@10.0.99.14 'date -u +%s')
    if ($LASTEXITCODE -ne 0) { throw 'Verifica SSH fallita.' }
    [long]$epochUbuntu = 0
    if (-not [long]::TryParse(($righeConfronto -join '').Trim(), [ref]$epochUbuntu)) { throw 'Risposta oraria non valida.' }
    $epochWindows = [DateTimeOffset]::UtcNow.ToUnixTimeSeconds()
    Write-Output ('Ubuntu UTC: ' + [DateTimeOffset]::FromUnixTimeSeconds($epochUbuntu).UtcDateTime.ToString('o'))
    Write-Output ('Windows UTC: ' + [DateTimeOffset]::FromUnixTimeSeconds($epochWindows).UtcDateTime.ToString('o'))
    Write-Output ('Scarto Windows - Ubuntu (secondi, incluso ritardo SSH): ' + ($epochWindows - $epochUbuntu))
}

Se lo scarto e di pochi secondi, le VM sono allineate per la prova breve:
non eseguire altri Set-Date. Riparti con una NUOVA sessione dell'orchestratore.
Se lo scarto e ancora di ore, invia queste tre righe: non invertire la copia.

NOTA
Il fuso orario impostato resta configurato dopo il riavvio.
Questo non crea una sorgente NTP continua: il precedente allineamento SSH
e una regolazione una tantum. Per stabilita nel tempo servira un server NTP
raggiungibile, interno o esterno, e la verifica della sorgente delle VM.
Non e possibile certificare l'ora reale solo copiando un orologio sull'altro.
